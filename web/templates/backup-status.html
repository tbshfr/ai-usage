Backups are off. To upload a compressed database snapshot to Amazon S3 or another S3-compatible service once a day:

  1. Create a private bucket and an access key that can write, list, and read objects in it.
  2. Set these environment variables for the ai-usage process: 
    AI_USAGE_BACKUP_S3_BUCKET=ai-usage-backups
AI_USAGE_BACKUP_S3_REGION=<REGION>
AI_USAGE_BACKUP_S3_PREFIX=prod/
AI_USAGE_BACKUP_S3_ACCESS_KEY_ID=<ACCESS_KEY_ID>
AI_USAGE_BACKUP_S3_SECRET_ACCESS_KEY=<SECRET_ACCESS_KEY>
# Only for services other than Amazon S3:
AI_USAGE_BACKUP_S3_ENDPOINT=<S3_API_URL>
  3. Restart ai-usage. The first backup runs right away and repeats daily at that time; this section then shows its status and lets you change the time.

For Amazon S3, use the bucket’s region and leave out the endpoint. Other services need the authenticated S3 API URL, not a public bucket URL, and the region they document (auto for Cloudflare R2). Use a unique prefix ending in / for each instance, and add a bucket lifecycle rule to delete old backups. With Docker Compose, also pass the variables through the service’s environment block. See the backup guide for retention, permissions, and restore.
